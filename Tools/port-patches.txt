# Line-preserving mechanical patches applied to upstream sources at build time by
# tools/gen-sources.ps1. Format (tab-separated, 3 fields):
#
#   <path-substring-filter>	<.NET regex>	<replacement>
#
# The path filter selects which upstream files a rule applies to (substring match, / separators).
# Rules are applied in order. A rule that changes the line COUNT of a file is rejected by the
# generator - patched files must keep upstream line numbers so stack traces and #line
# directives stay meaningful.
#
# Patched copies land in Core.Web/obj/patched/ and are compiled instead of the upstream file.

# --- P4a: ConfigurationElement/ConfigurationSection declare these members `protected internal`,
#          and upstream overrides them as `protected internal` too - which is legal only inside
#          the declaring assembly. C# (spec 15.6.4) requires an override of a `protected internal`
#          member from *another* assembly to be declared plain `protected`. Mono got away with it
#          because its System.Web and System.Configuration were built as friends; we reference the
#          shipping System.Configuration.ConfigurationManager, so drop the `internal`.
#          Verified: all ten members compile as plain `protected` against ConfigurationManager 8.0.0.
#          The referencesource/System.Web/Configuration files already use plain `protected` and
#          need no rule (checked: 0 of 113 declare `protected internal override`).
# --- P1: DynamicBase / PrivateBinPath / ApplicationName are AppDomainSetup properties that carry
#     no meaning on .NET Core (one AppDomain, no per-application setup). Redirect every read to
#     Core.Web/Port/PortPaths.cs, which the Kestrel host initialises. ApplicationBase is NOT
#     redirected - it works correctly and upstream reads it directly.
